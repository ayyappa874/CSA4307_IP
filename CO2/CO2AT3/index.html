Question 1: Responsive Web Design

5 marks

Concept

Responsive web design (RWD) makes one website adapt its layout, images and text to any screen size, so the same code works on mobile, tablet and desktop.

Importance

  • Most users browse on phones, so a fixed desktop layout is unusable for them.
  • One site is cheaper to build and maintain than separate mobile and desktop sites.
  • Better user experience, higher conversions and better search ranking.

Key CSS techniques

  • Viewport meta tag so phones use their real width.
  • Fluid layouts using %, fr, rem and max-width instead of fixed pixels.
  • Flexible images: max-width: 100%; height: auto;
  • Media queries to change the layout at breakpoints (600 px, 992 px).
  • Flexbox or Grid for layout, with a mobile-first approach.

Flexbox or Grid for adaptive layouts

Flexbox arranges items in one row or column and wraps them (flex-wrap). Grid defines rows and columns together; repeat(auto-fit, minmax(200px, 1fr)) changes the number of columns by itself.

Example layout

.lay { display: grid; gap: 10px; grid-template-columns: 1fr; }                    /* mobile: 1 column */
@media (min-width: 600px) { .lay { grid-template-columns: repeat(2, 1fr); } }   /* tablet: 2 */
@media (min-width: 992px) { .lay { grid-template-columns: repeat(4, 1fr); } }   /* desktop: 4 */

Question 2: Client-Side Validation

5 marks

Concept and purpose

Client-side validation checks form input in the browser, before it is sent to the server. It gives instant feedback, reduces server load and prevents obvious mistakes such as an invalid email.

JavaScript event handling in validation

Events trigger the checks: input (validate while typing), blur (when leaving a field) and submit (final check; event.preventDefault() stops sending if invalid).

Role of regular expressions

A regular expression describes the allowed pattern of text. regex.test(value) returns true or false. Email needs name@domain.ext; an Indian mobile number is exactly 10 digits starting with 6 to 9.

var emailRe = /^[A-Za-z0-9._%+-]+@[A-Za-z0-9-]+(\.[A-Za-z0-9-]+)*\.[A-Za-z]{2,}$/;
var phoneRe = /^[6-9][0-9]{9}$/;
email.addEventListener("input", function () {
  if (emailRe.test(email.value)) { error.innerHTML = ""; } else { error.innerHTML = "Invalid email"; }
});
Live example (errors appear as you type)

Improvements

Usability: clear error text, green and red borders, type="email" and type="tel" keyboards, error messages linked with aria-describedby. Security: client-side checks can be bypassed, so always validate again on the server, sanitise input and use HTTPS.

Question 3: Box Model, Positioning and Breaking Layouts

5 marks

CSS box model

Every element is a rectangle made of four layers, from inside to outside: content (text or image), padding (space inside the border), border, and margin (space outside).

margin
content

Orange = margin, black = border, green = padding, blue = content

Positioning and layout structure

  • static: normal flow (default).
  • relative: shifted from its normal place, still keeps its space; anchor for children.
  • absolute: removed from the flow and placed against the nearest positioned parent. Other elements ignore it, so overlap can happen.
  • fixed stays on screen while scrolling; sticky sticks after a scroll point.

Causes of layout breaking

  • Fixed pixel widths and heights.
  • Absolute positioning used for page structure.
  • Padding and border added to width (content-box), so totals exceed 100%.
  • Floats that are not cleared, negative margins, missing media queries.

Fixing with media queries and best practices

* { box-sizing: border-box; }                      /* padding and border stay inside width */
.container { display: flex; flex-wrap: wrap; gap: 10px; }
.sidebar { flex: 1 1 200px; }
.main    { flex: 3 1 350px; }
@media (max-width: 600px) { .container { flex-direction: column; } }   /* stack on phones */

Best practices: use border-box; use Flexbox or Grid, not absolute positioning, for structure; use %, rem, min-height and max-width instead of fixed sizes; design mobile-first; test at many widths.

Question 4: DOM and Dynamic Content

5 marks

Document Object Model (DOM)

The DOM is a tree of objects that the browser builds from the HTML page. Each tag becomes a node that JavaScript can read and change. It connects the page to JavaScript and makes pages interactive.

Updating the page without reloading

JavaScript finds elements (getElementById, querySelector), then changes them (textContent, classList, createElement, appendChild, removeChild). Only that part of the page is redrawn; no reload is needed.

var li = document.createElement("li");
li.textContent = input.value;
list.appendChild(li);                 // new item appears instantly

    Use textContent instead of innerHTML for user text (prevents XSS), event delegation (one listener on the list), DocumentFragment or batch updates for many items, and show loading and success messages.

    5 marks
    A college website must display properly on desktops, tablets and mobile phones.

    Question 7: Navigation Menu Overlapping on Small Screens

    5 marks
    A navigation menu overlaps its content on smaller screens.

    Cause

    The menu uses fixed widths, a fixed height, float or position: absolute. Its items cannot wrap, so they overflow and cover the content below.

    Solution with CSS layout techniques

    • Make the menu a flex container with flex-wrap: wrap; each link uses flex: 1 1 auto.
    • Remove the fixed height (use padding) and keep the menu in the normal flow, not absolute.
    • On phones, stack links with flex-direction: column or use a hamburger menu.
    nav { display: flex; flex-wrap: wrap; }
nav a { flex: 1 1 auto; padding: 12px 16px; text-align: center; }
@media (max-width: 600px) { nav { flex-direction: column; } }

    Question 8: JavaScript Validation of Empty Fields

    5 marks
    A registration form accepts empty fields.
    • Listen for the form's submit event and call event.preventDefault().
    • Read each field's value, use trim() so spaces alone do not count, and check if it is empty.
    • Show an error under each empty field, and only continue when all fields are filled.
    form.addEventListener("submit", function (e) {
  e.preventDefault();
  var ok = true;
  if (name.value.trim() === "") { nameErr.innerHTML = "Name is required"; ok = false; }
  if (ok) { message.innerHTML = "Registered successfully!"; }
});

    Question 10: Updating Total Price from Quantity

    5 marks
    A shopping website needs to update the total when the quantity changes.
    • Store the unit price, and listen for the quantity field's input event.
    • Read the quantity with parseInt, and check it is a valid number of at least 1.
    • Calculate total = price * quantity and display it with textContent.
    var price = 499;
qty.addEventListener("input", function () {
  var q = parseInt(qty.value, 10);
  if (isNaN(q) || q < 1) { q = 1; }
  total.textContent = "Rs. " + (price * q);
});
