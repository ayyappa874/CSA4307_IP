Question 1 (4 marks)

Responsive Navigation Bar Design

The navigation bar at the top of this page is the live demo. Resize the window below 768 px to see the hamburger menu.

(a) Key components of an e-commerce navigation bar

  • Brand logo linking to the home page
  • Main links: Home, Shop, Categories (dropdown), Deals, Contact
  • Search bar to find products quickly
  • Shopping cart icon with item count, plus account/login and wishlist
  • Hamburger button for small screens

(b) Design with CSS

  • Flexbox aligns logo, cart and menu in one row and wraps when space ends.
  • Mobile-first: the base CSS is the mobile layout; one min-width: 768px media query turns it into a horizontal bar.
  • position: sticky keeps the bar visible while scrolling; z-index keeps it above content.
  • Links are padded to at least 44 px tall so they are easy to tap.

(c) Adaptation to smaller screens

  • Mobile (below 768 px): links are hidden; the hamburger button shows them as a vertical list.
  • Tablet and desktop (768 px and above): the hamburger hides and the links appear in a row; Categories opens on hover.
.menu { display: none; flex-direction: column; }     /* mobile */
.menu.open { display: flex; }
@media (min-width: 768px) {
  .burger { display: none; }
  .menu { display: flex; flex-direction: row; }
}

(d) Evaluation and improvements

  • Good: works without scrolling sideways, large tap targets, keyboard focus style, no framework needed.
  • Improve: keep the search bar visible on mobile, add a mega-menu for many categories, close the menu when tapping outside, highlight the current page, add a "skip to content" link and an icon-only cart on very small screens.

(a) Suitable CSS properties

  • :hover and :focus-within selectors to trigger the effect
  • transform (translate, scale), box-shadow, opacity, background-color, border-color, filter
  • transition (duration, timing function) and cursor: pointer

(b) Suitable transition or animation

OptionUse
transition: transform 0.3s easeBest for hover. Smooth change between two states, no extra code.
@keyframes animationFor repeating or multi-step effects (for example a pulsing "Sale" badge).

Choice: transition, 0.3 s with ease, because hover is a simple two-state change.

(c) Design of the hover effect

.card { transition: transform 0.3s ease, box-shadow 0.3s ease; }
.card:hover { transform: translateY(-8px);
              box-shadow: 0 14px 26px rgba(0,0,0,0.25); }
.card:hover .pic { transform: scale(1.15); }
.card:hover .add { transform: translateY(0); }   /* button slides up */

(d) Performance and user experience

  • Animate only transform and opacity. The browser handles these on the GPU, so no re-layout. Animating width, height, top or margin makes the page jerky.
  • Keep durations at 200 to 400 ms so it feels quick but visible.
  • Touch screens have no hover, so @media (hover: none) shows the button always.
  • :focus-within gives keyboard users the same effect.
  • prefers-reduced-motion turns animations off for users who are sensitive to motion.

(a) Layout requirements of a dashboard

  • Rows: header, then stat cards, chart and table below
  • Columns: fixed sidebar plus a flexible main area
  • Alignment: cards the same height, content aligned in both directions, consistent gaps
  • Reflow to one column on phones

(b) Flexbox compared with Grid

PointFlexboxGrid
DimensionOne dimension (row or column)Two dimensions (rows and columns together)
ApproachContent-first: items decide the sizeLayout-first: you define the tracks
PlacementOrder and alignment along one axisExact cells and named areas (grid-template-areas)
Best forNavbars, button groups, card contentPage and dashboard layouts, galleries
SpanningHardEasy (grid-column: 1 / -1)

(c) Choice and justification

CSS Grid for the dashboard frame, because the layout needs rows and columns at once, spanning cells (header across the top, sidebar down the side) and a layout that can be redefined in one place with named areas. Flexbox is still used inside single widgets, for example aligning items inside a stat card.

(d) Scalability and responsiveness

  • repeat(auto-fit, minmax(110px, 1fr)) adds or removes stat cards by itself as width changes.
  • New widgets only need a new grid area; no HTML restructuring.
  • One media query redefines the whole layout, with no JavaScript.
  • Limit: very old browsers (such as IE10) lack modern Grid support, which is rarely a concern today.

Why mobile-first works

Start with the small screen, keep only what matters, then add space and columns as the screen grows. The text line stays about 65 characters wide so it is easy to read.

.blog { display: grid; grid-template-columns: 1fr; gap: 14px; }   /* mobile */
@media (min-width: 768px) {
  .blog { grid-template-columns: 2fr 1fr; }                        /* article + sidebar */
  .blog .full { grid-column: 1 / -1; }
}

(a) Key sections of a blog layout

Header with logo and navigation, featured image, article list or post content, sidebar (categories, recent posts, search), comments, and footer.

(b) Mobile-first design

Base CSS is a single column with stacked sections, fluid width and readable text. No media query is needed for phones, so they download the simplest CSS.

(c) Scaling to larger screens

At 768 px a min-width media query makes two columns (article 2fr, sidebar 1fr), with header and footer spanning both. Larger screens could add a third column or a wider container.

(d) Accessibility and readability

  • Readability: font size 16 px or more, line-height 1.6, line length near 65 characters (max-width: 65ch), generous spacing.
  • Accessibility: semantic tags (header, article, aside, footer), heading hierarchy, text contrast of at least 4.5:1, alt text on images, visible focus outlines, no fixed-size text.
  • Improve: add a skip link, a dark mode and a print stylesheet.

(a) Appropriate JavaScript events

  • click: open or close the menu (works on mouse and touch)
  • mouseenter / mouseleave: hover highlight on desktop
  • keydown: Esc closes the menu; Enter and Space on buttons for keyboard users
  • focus / blur, and resize (reset the menu when the window grows)

(b) Event handling logic for the toggle

On click: find the panel, remember if it was open, close all panels, then open this one only if it was closed. Update aria-expanded so screen readers know the state.

button.addEventListener("click", function () {
  var panel = document.getElementById(this.dataset.target);
  var wasOpen = !panel.hidden;
  closeAll();
  if (!wasOpen) { panel.hidden = false; this.setAttribute("aria-expanded", "true"); }
});

(c) Implementation for user actions

Click toggles the panel, mouseenter and mouseleave add and remove a highlight class, and keydown for Esc calls closeAll(). The navbar hamburger at the top of this page uses the same toggle idea with a CSS class (open).

(d) Performance and improvements

  • Toggle CSS classes or the hidden attribute instead of setting many inline styles.
  • Use event delegation (one listener on the menu) when there are many items.
  • Debounce resize handlers; use passive listeners for touch and scroll.
  • Close the menu on outside click, add arrow-key navigation and focus trapping for accessibility.
